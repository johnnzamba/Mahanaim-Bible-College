# Deployment and operations

How to run the Digital Campus in staging and production. Payments have their own guide in
[`MPESA.md`](MPESA.md); the role matrix is in [`ROLES.md`](ROLES.md).

## Requirements

| Component | Version / note |
| --- | --- |
| Frappe Framework | v16 (Python 3.14, Node 24) on a standard `bench` |
| MariaDB | 11.x, `utf8mb4` |
| Redis | cache + queue (bench defaults) |
| wkhtmltopdf | 0.12.6 **with patched Qt** (for PDF letters, receipts, transcripts and certificates) |
| Fonts | DM Sans and Libre Baskerville installed system-wide, so PDFs match the screen |
| Optional | ERPNext (accounting posting), Frappe LMS (learning engine behind the LMS bridge) |

The React SPA is **pre-built and committed** (`mahanaim/public/app/` and `mahanaim/www/mbc.html`), so the
server does not need to build the frontend. Rebuild it on a workstation (`cd frontend && npm ci && npm run build`)
and commit the result; CI fails if the committed bundle is stale.

## First install

```bash
bench get-app https://github.com/johnnzamba/Mahanaim-Bible-College.git
bench new-site campus.mahanaim.ac.ke --admin-password '<strong password>'
bench --site campus.mahanaim.ac.ke install-app mahanaim      # roles, settings, study modes, fee components, grading scale
bench --site campus.mahanaim.ac.ke set-config host_name https://campus.mahanaim.ac.ke
bench --site campus.mahanaim.ac.ke enable-scheduler
sudo bench setup production <unix-user>                      # nginx + supervisor (web, workers, socketio, scheduler)
bench setup backups                                          # cron job for scheduled backups
```

`host_name` matters: M-Pesa callbacks, verification QR codes, email links and the PWA all use it.

Then sign in as Administrator at `/signin`:

1. **Settings → General**: college name, contacts, currency, logo.
2. **Settings → Master data**: campuses, departments and study modes.
3. **Academics → Calendar**: academic year, terms and intakes; set the current term.
4. **Academics → Grading**: review the seeded scale (A to F on a 4.0 GPA, with Distinction/Credit/Pass
   classification) and adjust it to the approved academic policy.
5. **Staff**: create staff members and give each the right roles (see `ROLES.md`).

For a demo or UAT site, `bench --site <site> execute mahanaim.demo.seed.run` loads sample data. Demo accounts
use the `@mahanaim.demo` domain; never run the seed on production.

## Site configuration

| Key | Purpose |
| --- | --- |
| `host_name` | Public base URL (required) |
| `mahanaim_pdf_zoom` | PDF zoom factor. The default 1.3 compensates for unpatched-Qt wkhtmltopdf; use `1` with patched Qt |
| `encryption_key` | Generated by Frappe; back it up separately, because encrypted secrets and backups depend on it |
| `throttle_user_limit` | Most user accounts Frappe allows to be created per hour (default 60). Applicant sign-ups and direct student, staff and sponsor creation each add an account, so raise this (e.g. `500`) during application peaks or intake week |

Setup sets **System Settings → Time Zone** to `Africa/Nairobi` if it is blank (Frappe otherwise assumes
Asia/Kolkata, which skews exam windows and due dates); change it there if the college runs elsewhere.

Never set `ignore_csrf` or `developer_mode` in production. Keep `mute_emails` off in production and on in
staging, unless staging should really send mail.

## Email and SMS

- **Email**: add an outgoing **Email Account** (Desk → Email Account) and mark it default. Every notification
  is also written to **Message Log** (visible in Admin → Communication → Message log).
- **SMS**: **Settings → Communication** (`Mahanaim Settings → SMS Gateway`). Choose **Africa's Talking**
  (username, API key, sender ID; the username `sandbox` uses the sandbox host) or a **Generic** HTTP gateway
  (URL plus a JSON payload template with `{to}`, `{message}` and `{sender}`). Turn on `sms_enabled`, then use
  *Send test SMS*. Failed messages can be retried from the message log.
- Templates for every event (OTP, application received, decisions, payments, results…) are editable under
  Admin → Communication → Templates. Events without a template fall back to built-in text.

## Payments (M-Pesa Daraja)

Follow [`MPESA.md`](MPESA.md). In short:

- **Callback URLs**: STK `/api/method/mahanaim.api.mpesa.stk_callback`; C2B validation and confirmation
  `/api/method/mahanaim.api.finance.paybill_validation` and `.../paybill_confirmation`. Daraja's RegisterURL
  rejects URLs containing "mpesa" or "safaricom", which is why C2B uses the finance aliases.
- These URLs must be reachable over public HTTPS. Every callback carries the secret `?token=` from M-Pesa
  Settings; callbacks without it get HTTP 403. Register the C2B URLs once from Admin → Settings →
  Integrations.
- Simulation mode is for demos only; switch it off before going live.

## Security checklist

- HTTPS only, with a firewall/WAF in front of nginx. Expose ports 80 and 443 only; MariaDB and Redis must not
  be reachable from outside.
- **Admin MFA Required** on (Mahanaim Settings). Staff then need the emailed code after their password, and
  the `on_login` hook blocks every other sign-in route for staff.
- System Settings: **Allow Consecutive Login Attempts** (e.g. 5), **Allow Login After Fail** (e.g. 300 s),
  a minimum password score, and session expiry.
- OTP length, expiry, attempts and resend cooldown are in Mahanaim Settings → Security.
- Grant Desk access (System Manager) to as few people as possible; day-to-day work happens in the portals.
- Review Admin → Audit (document changes and sign-in activity) regularly.
- One-time codes and password-reset links are redacted in the Message Log. Never set `mahanaim_log_secrets`
  in production; it is a development switch that keeps them readable.

## Background jobs

Supervisor runs the workers and the scheduler. The app's jobs (`hooks.py`):

| Schedule | Job |
| --- | --- |
| every 5 min | expire stale M-Pesa requests; auto-submit exam attempts past their deadline; dispatch scheduled announcements |
| hourly | open and close exams on schedule; reconcile online giving with M-Pesa |
| daily | mark overdue invoices; fee reminders; event statuses; overdue library loans; purge expired OTPs; assignment due reminders; termly sponsor reports (sent once, 14 days after a term ends) |

Realtime features (notification bell, exam monitor) need the **socketio** process from `bench setup production`.

## Backups and restore

- `bench setup backups` schedules database and files backups. Set **System Settings → Encrypt Backups** and
  keep `encryption_key` safe.
- Copy `sites/<site>/private/backups/` off the server every day (rsync, object storage or an offsite backup
  app). A backup that lives only on the server is not a backup.
- To restore onto a fresh bench:

  ```bash
  bench --site <site> restore <db.sql.gz> \
    --with-public-files <files.tar> --with-private-files <private-files.tar> \
    [--encryption-key <key>]
  bench --site <site> migrate
  ```

- Rehearse a restore on staging every quarter, and before go-live.

## Monitoring

- **Desk → Error Log** and **Scheduled Job Log**: failed jobs and exceptions.
- **Message Log**: failed SMS or email (status Failed, with the provider response).
- **M-Pesa**: Admin → Finance → M-Pesa lists requests stuck in Pending and unmatched C2B payments.
- `bench doctor` checks the scheduler and workers; add an uptime probe on `/api/method/ping`.

## Upgrades

```bash
bench backup --with-files
bench update --pull --apps mahanaim      # or: cd apps/mahanaim && git pull
bench --site <site> migrate
bench restart
```

Rehearse on staging first. `migrate` applies doctype changes and patches. The committed SPA bundle ships
with the app, so there is no separate frontend deploy.
